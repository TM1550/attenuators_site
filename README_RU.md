# Каталог аттенюаторов на Firebase Spark

Комплект: публичный каталог из Firestore, страница администратора для импорта, правила доступа и 77 существующих записей. Настройка Firebase и развёртывание выполняются в вашем проекте. В комплекте нет ваших паролей и конфигурации проекта.

## 1. Создайте проект на бесплатном плане

1. Откройте https://console.firebase.google.com/ и нажмите «Create a project / Создать проект» либо откройте существующий.
2. Для нового проекта Google Analytics можно не включать.
3. Убедитесь, что выбран **Spark**, без подключения платёжного аккаунта. Blaze для этого комплекта не нужен.
4. Запишите **Project ID** из Project settings → General. Это не отображаемое название проекта.

Используются Cloud Firestore Standard, Authentication Email/Password и обычный Firebase Hosting. Cloud Functions, Cloud Run, App Hosting и Cloud Storage не требуются. Для Cloud Functions нужен Blaze — поэтому собственный серверный API из предыдущего предложения здесь заменён прямым Firebase SDK с ограничением записи по UID.

Официальные условия Spark: https://firebase.google.com/docs/projects/billing/firebase-pricing-plans

## 2. Создайте Firestore

1. Откройте Firestore Database (обычно раздел Build).
2. Нажмите Create database. Выберите **Standard edition / Native mode**, если предлагается выбор, и базу **(default)**.
3. Выберите регион, подходящий для вашей аудитории. Считайте выбор региона постоянным: перенос потребует отдельной миграции.
4. Выберите **Production mode**. Временно закрытая база — ожидаемое состояние. Не включайте test mode.
5. Не создавайте коллекции вручную: их создаст импортёр.

Бесплатные квоты Firestore: 1 GiB хранения, 50 000 чтений документов в день, 20 000 записей в день, 20 000 удалений в день и 10 GiB исходящего трафика в месяц. Квоты и условия проверяйте в документации: https://firebase.google.com/docs/firestore/quotas

## 3. Создайте пользователя администратора

Ваш аккаунт входа в Firebase Console и пользователь Firebase Authentication — разные сущности.

1. Authentication → Get started → Sign-in method → Email/Password → Enable → Save. Не нужен вход по телефону.
2. Authentication → Users → Add user: создайте email и пароль для входа в импортёр. Пароль может отличаться от пароля Google/email.
3. Скопируйте **UID** созданного пользователя.
4. Если запускаете локально, откройте Authentication → Settings → Authorized domains и добавьте `localhost`, если его нет. Для нового собственного домена также добавьте его. Домены Firebase Hosting проверьте в этом списке.

Инструкция Firebase: https://firebase.google.com/docs/auth/web/password-auth

## 4. Зарегистрируйте веб-приложение и заполните конфигурацию

1. Project settings → General → Your apps → значок `</>` (Web).
2. Укажите имя, например `attenuators-catalog`, и зарегистрируйте приложение.
3. В SDK setup and configuration выберите Config.
4. Скопируйте значения `apiKey`, `authDomain`, `projectId`, `appId` в **public/firebase-config.js**. Если Firebase выдал дополнительные поля, их тоже можно оставить в объекте конфигурации. Имена экспортов менять не нужно.
5. В том же файле замените `PASTE_ADMIN_UID` на UID администратора.
6. В **firestore.rules** замените `PASTE_ADMIN_UID` на ТОТ ЖЕ UID. Именно правила Firestore ограничивают доступ; переменная в браузере только управляет интерфейсом.

Конфигурация веб-приложения и UID не являются паролем. Никогда не помещайте в public/ JSON-ключ service account, секретный ключ сервера или пароль. Здесь они не нужны.

SDK подключается как JavaScript-модули через официальный CDN, версия 13.1.0 зафиксирована одинаково во всех файлах. Документация: https://firebase.google.com/docs/web/alt-setup

## 5. Опубликуйте правила и сайт

Установите актуальный Node.js LTS и npm. Откройте терминал в корне распакованной папки — там, где лежит firebase.json.

```sh
npm install -g firebase-tools
firebase login
firebase deploy --project YOUR_PROJECT_ID --only firestore:rules,hosting
```

Вместо `YOUR_PROJECT_ID` укажите свой Project ID. Конфигурация firebase.json уже подготовлена, `firebase init` не требуется. Не выбирайте App Hosting и не соглашайтесь на перезапись index.html.

Команда публикует правила и содержимое public/. Папка data/ с исходными JSON не публикуется. Сайт будет доступен по адресу:

```text
https://YOUR_PROJECT_ID.web.app/
```

Можно сначала опубликовать только правила:

```sh
firebase deploy --project YOUR_PROJECT_ID --only firestore:rules
```

И запустить локальный HTTP-сервер в public/:

```sh
cd public
python -m http.server 8000
```

Адрес каталога: http://localhost:8000/ ; импортёр: http://localhost:8000/admin.html . В Windows вместо `python` при необходимости используйте `py`. Открытие HTML двойным щелчком через file:// не подходит для модулей Firebase. Локальный сервер обращается к настоящей базе вашего проекта: это не эмулятор.

Документация Hosting: https://firebase.google.com/docs/hosting/quickstart

## 6. Загрузите ваши 77 записей

1. Откройте `/admin.html` на своём сайте.
2. Войдите email/паролем пользователя из шага 3. Страница покажет UID и статус администратора.
3. Выберите **data/attenuators_77.json** на компьютере.
4. Нажмите «Проверить совпадения». Для пустой базы ожидается: новых 77, уже есть 0, требуют проверки 0.
5. Нажмите «Импортировать новые». Записи будут добавляться по одной атомарной транзакцией.
6. Откройте каталог и нажмите «Обновить». Должны появиться 77 систем.
7. Повторная проверка того же файла должна показать 77 существующих записей, а не ещё 77 новых.

Нажатие «Проверить» не пишет данные. Импорт никогда не перезаписывает существующие записи. Если сеть оборвётся, повторите импорт: сохранённые записи будут пропущены.

## 7. Как добавлять новые элементы

1. Скопируйте **data/new_record_template.json**. Замените ID на следующий свободный, например TA078, и все шаблонные значения.
2. `identity_key` — постоянный ключ конкретного регуляторного участка. Например: `v1|bacillus-subtilis|new-locus|leader-1`. Он назначается один раз, а не пересчитывается из изменяемого описания. Не меняйте его при исправлении лиганда, названия или механизма.
3. Укажите `organism`, точный `target`, известные `aliases`. Можно добавить `taxon_id`, `strain`, `locus_tag`, `assembly_accession`, `coordinates`, `strand`: они сохранятся и будут доступны в JSON/поиске.
4. Для новой, ещё не проверенной находки оставьте `status: "candidate"`. Она видна администратору и участвует в проверке дубликатов, но не показывается в публичном каталоге.
5. Для проверенного элемента задайте `status: "confirmed"`, `transcription_attenuation_confirmed: true`, заполните `evidence_level`, `experimental_evidence`, `limitations` и `references`. Минимум у одной статьи отметьте `own_transcription_experiments: true`. Это декларация куратора: программа не проверяет содержание статьи автоматически.
6. В импортёре выберите JSON или вставьте объект в поле и нажмите «Проверить совпадения».
7. Статусы: «Новая» допускается к импорту; «Уже есть» пропускается; «Возможный дубликат» блокируется и требует сопоставления локусов, штаммов, координат и статей.

Пример references:

```json
[
  {
    "title": "Точное название реально проверенной статьи",
    "doi": "DOI статьи",
    "url": "https://doi.org/DOI_СТАТЬИ",
    "year": 2026,
    "own_transcription_experiments": true,
    "mentions_transcription_attenuation": true,
    "experimental_evidence": "Какие опыты авторы провели именно с этим участком"
  }
]
```

Это образец структуры, а не готовая библиографическая запись.

## 8. Как работают дубликаты и каковы границы проверки

- ID документа Firestore — SHA-256 нормализованного `identity_key`.
- Создание выполняется в транзакции. Два одновременных импорта одинакового ключа создадут один документ.
- Изменение имени или DOI при сохранении ключа не создаёт новый элемент.
- Сравниваются также ID, организм и target/aliases. Например, ykoK и mgtE связаны синонимами у B. subtilis.
- В одном импортируемом файле повторы тоже пропускаются.
- Другой вид не объединяется автоматически с тем же названием гена.
- Строковое сравнение не распознает неизвестный синоним, ошибку таксономии или два разных ключа одного участка без общих названий. Такие случаи требует научной проверки.
- Для старых 77 записей ключи закреплены вручную; не все участки имеют точные координаты. Это не геномный реестр с гарантией биологической уникальности.
- Проверка возможных совпадений выполняется по снимку базы и повторяется перед импортом. Защита от гонки гарантирована для одинакового identity_key; два разных ключа одного биологического участка требуют ручного объединения.
- Прямые изменения через Firebase Console обходят проверку импортёра. Не создавайте записи вручную с произвольными документ-ID.

Здесь одна коллекция `attenuators`, статьи и доказательства вложены в запись. Для 77 систем это проще и дешевле по чтениям, чем несколько связанных коллекций. При необходимости позже можно вынести статьи в отдельную коллекцию без смены стабильных ключей.

## 9. Обновление существующей записи и резервная копия

Перед редактированием нажмите «Скачать полную базу» в импортёре. Публичный каталог также умеет экспортировать JSON, но только подтверждённые записи.

Импортёр предназначен для безопасного добавления, а не замены существующих данных. Для редактирования найдите документ в Firebase Console по полю id и исправьте нужные поля. Сохраните id, identity_key и identity_hash. Для публикации кандидата заполните доказательства и поставьте status = confirmed. Правила SDK требуют updated_at как serverTimestamp; ручное редактирование Console выполняется владельцем проекта отдельно и не вызывает эту проверку.

Не меняйте ключ для обхода «Уже есть»: новую статью нужно добавить в references существующего документа. Административное удаление интерфейсом запрещено; для снятия с публикации задайте status = rejected. Секретных данных в записях быть не должно: confirmed-документ читается публично целиком, включая все его поля.

## 10. Чтения и бесплатный план

Каталог делает один запрос при открытии и ещё один по кнопке «Обновить». Подписок реального времени нет. Поиск и фильтры работают на уже загруженных данных и не делают новых запросов.

77 документов — примерно 77 документных чтений на одно полное открытие; 500 открытий — около 38 500 чтений, без учёта импорта, администратора и других клиентов. Это оценка, а не гарантия квоты. Не нажимайте многократно «Обновить». Следите за Firestore → Usage и Hosting → Usage. На Spark превышение квоты приводит к ограничениям сервиса, а не автоматическому платному масштабированию.

Данные доступны, пока есть интернет, работает CDN Firebase и не исчерпаны квоты. При ошибке сайт показывает сообщение, не выдавая пустой список за успешную загрузку.

## 11. Проверка базы из следующего чата

Скачайте актуальный JSON из каталога или административную выгрузку и передайте его вместе с новой находкой. В файле сохраняются identity_key, aliases, организм, мишень и источники. Этого достаточно для программного сопоставления и научной проверки спорных совпадений.

Свой серверный REST API не развёрнут: для Spark используется Firebase SDK/стандартный API Firestore. Постоянного доступа ассистента к базе нет. Не передавайте пароль администратора или service-account ключ в чат.

## 12. Проверки кода и типичные ошибки

```sh
npm test
```

Тесты проверяют 77 уникальных ключей, повторный импорт, дубликат внутри файла, ykoK/mgtE, отличие видов, ID-конфликт, требования к экспериментальным данным и запрет небезопасных ссылок.

- `permission-denied`: UID в правилах не совпадает, правила не опубликованы или выполнен вход другим пользователем.
- `auth/operation-not-allowed`: не включён Email/Password.
- `auth/invalid-credential`: неверный email/пароль созданного Authentication-пользователя.
- «Заполните firebase-config.js»: остались PASTE_ значения.
- В каталоге 0 записей: база пуста либо нет status = confirmed.
- Ошибка SDK/CDN: проверьте сеть и блокировщики; версия всех трёх Firebase SDK должна совпадать.
- Квота/RESOURCE_EXHAUSTED: проверьте Usage и дождитесь восстановления соответствующей квоты; не переходите на Blaze, если нужен строго бесплатный проект.

Подключение к вашему настоящему Firebase-проекту не тестировалось: Project ID, конфигурация и учётная запись пока не предоставлены. Правила следует опубликовать и проверить на своём проекте: посторонний пользователь может читать confirmed, но не может создавать/изменять документы; администратор может импортировать. Библиографические ссылки перенесены из вашего каталога, а не проверены заново в этой технической задаче.
